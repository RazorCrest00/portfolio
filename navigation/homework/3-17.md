```python
# CODE_RUNNER: 3.17 Homework - Library workload calculator

def catalog_work(n):
    if type(n) is not int or n < 0:
        raise ValueError("Book count must be a nonnegative whole number")
    return {"books": n, "visits": n, "ordered_pairs": n * n}

for n in [12, 24, 0]:
    report = catalog_work(n)
    print("Books:", report["books"])
    print("Single-pass visits:", report["visits"])
    print("Ordered pairs (including self-pairs):", report["ordered_pairs"])
```

The two models represent **different tasks**: visiting every entry versus considering every ordered pair, including self-pairs and both orders. Scanning cannot replace pairing if the task needs pairs. Doubling `n` gives `2n` visits but `(2n)² = 4n²` pairs. AP notation writes these assignments as `visits ← n` and `pairs ← n * n`.

**Recommendation and tradeoffs:** An unsorted catalog cannot safely use this binary search. For one lookup, linear scanning can avoid sorting work. For repeated lookups, sorting first may be worthwhile, but preprocessing and updates must be counted. Keeping an extra sorted copy needs extra memory proportional to the catalog size; sorting the original may change its order. The counts alone do not establish which full application runs fastest.

## Design Thinking

- **Need:** A librarian must understand how search and catalog tasks scale without interpreting unexplained numbers.
- **Goal:** Give correct, clearly labeled counts and a recommendation with its assumptions.
- **Choices:** Compare a single scan, repeated halving of sorted data, and ordered-pair work; distinguish tasks and preprocessing costs.
- **Prototype:** The supplied numeric calculator adapted to 12 books, a doubled input, and a named result dictionary.
- **Actual revision:** Replace bare numbers with labels identifying books, visits, and ordered pairs, including the self-pair rule. Verify 12 → 12/144, 24 → 24/576, and 0 → 0/0 after the change. This records a code revision and test, not invented peer feedback.

Polynomial growth or lower is classified as reasonable time in AP CSP; exponential and factorial growth are examples of unreasonable time as inputs grow. That classification is not a promise that every large input finishes quickly. A short-books-first heuristic may produce a useful reading list quickly while missing a more enjoyable combination.
